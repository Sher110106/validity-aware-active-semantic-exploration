### Offline audit and reviews (exploratory)

Source: `SYNTHESIS_AND_NEXT_PLAN.md` §1-5 and §8; WRITEUP §4.

- **What the score measures.** ASP scores a view by the mutual information between the next view and which ensemble member is right (`calculate_uncertainty.py:501-549`). It has no term for truth and none for unknown space.
- **Content and decisions.** On 121 official-arm stages, swapping DeepSeek's guesses for random ones moved the top-scored candidate no more than swapping one random set for another. The difference beyond the redraw floor was +0.09 m (CI −0.25 to +0.38), and −0.04 m on counted runs.
- **Ranking, exact objects.** With exact objects, the score ranks views by true unseen objects (median ρ about 0.45; 0.39-0.48 by arm). This is partly by construction, because the oracle sets come from the objects the yardstick counts.
- **Ranking, DeepSeek.** With DeepSeek's guesses the score barely ranks views. On the same official stages, median ρ is 0.20 against 0.19 for a placebo set (paired +0.07, mostly on 00853).
- **Yield.** About 1 in 12 unseen objects counted in view of a stop reach the next map. Part of that gap is the detector, and part is the yardstick, which ignores unmapped walls.
- **Repeat runs.** Same-seed runs split at the first stop.
- **What the author missed** (synthesis §3, nine items), among them:
  - no placebo or content control;
  - one run per scene;
  - a self-built reference;
  - a room plan that is computed but never used.

## 9. Host traps

- **The OpenRouter shim has two copies.** The LLM logger imports the shim from the venv's site-packages copy, not from `/workspace/tools/llm_openrouter/`. Update both.
- **Stopping a run.** Killing a pipeline leaves multiprocessing workers calling the paid LLM. Kill every process in the container except PID 1.
- **`pgrep -f` over ssh.** `pgrep -f <pattern>` inside `ssh '...'` matches the remote shell itself; killing its result once killed my own session. Anchor the pattern.
- **Failed checks.** A failed `docker exec` must read as "unknown", never "gone".
- **Root-owned files.** Containers wrote the run directories, `runs/live_campaign/hm3d_refs_work/`, the old ledgers and `tools/live_policy/__pycache__`, so all are root-owned.
  - Run host-side analysis inside `asp-noetic` with `/workspace/environments/semantic_perception/bin/python`, and write through the container.
  - The containers memory names for this (`asp-noetic-e` read-only, `asp-noetic-d` for writes) no longer exist.
  - Check syntax with `ast.parse`, not `py_compile`.
- **Logs.** `rospy.loginfo` output goes to the container's `/root/.ros/log/<uuid>/rosout.log`, not the run's `exploration_pipeline.log`.
- **Frontier maps.** Frontier runs need a post-run DSG-to-YAML conversion (`runs/frontier_seeds/convert_runs.sh` on the host).
- **Credentials** (`.gemini_credentials`, `.openrouter_credentials`, `.hm3d_credentials`, `.cvp-secrets/*`): never read or print them.
  - Use them only inside containers.
  - `run_live_run.sh` sources `.openrouter_credentials`.
  - The Gemini key in `.cvp-secrets/` is a raw key file that `load_credential()` reads; do not source it.
