# Fable review of the ASP course, 2026-10-28

Final assessment after a fact-check and a red-team pass. Verdict: **continue_with_changes**.

## Answer

The verdict label stays continue_with_changes, but the recommended option changed. Keep the queue running to the end of E1 and E2; drop the promise to live-test another LLM; fix the deck. What I withdraw is the oracle arm as the endsem centrepiece and the "placebo = DeepSeek <= oracle, Gemini in between" bracket. Three critiques forced that, and the files support all three. First, I read "DeepSeek carries no signal" off the 0.5 m radius; the same score files give DeepSeek 24.7% within 2 m against placebo 7.4% and Gemini 28.3% (gemini_static*_scores.json), and calculate_uncertainty.py keeps only candidate poses within camera range of a hypothesised object, so the planner's sensitivity is at metres, not half a metre. DeepSeek's guesses are right about the area and wrong about the half-metre, and the live null says the ASP loop does not turn even that coarse signal into map gain. A precision-ordered bracket would place Gemini next to DeepSeek, not between it and an oracle. Second, the oracle is new code with no job kind in campaign_chain.sh, a new pre-registration, 16 to 30 h of paired host time on a host that has had an incident in every wave, and no positive control; a check-in cannot promise it. Third, the midsem deck framed the project as the validity layer and put "changing the LLM" out of scope, so the endsem should close the layer, with the placebo test as the reason it cannot help on this model. I also accept the numeric corrections: the MDE range is 0.014 to 0.03 (my stats.py counted the official cells twice), the frontier comparison sentences were wrong at 60 m (five live runs on 00853, one placebo above the frontier; the 00871 placebo below it), the Gemini chart's "8 saved inputs" is right and the DeepSeek and placebo bars should be recomputed on those 8 (2.1% and 1.4% at 0.5 m), inflation at 60 m is 2.9x and 4.5x, and a Gemini live run costs $90 to $200, so the case against it is that one seed proves nothing and the balance is unconfirmed, not that one run exceeds the credit. I reject one red-team claim as stated: filter_only is not "at or above official on both scenes under both references" (00871, frontier reference: 0.4643 sits between 0.4617 and 0.4670), though E2 is open and I should not have written its null into the endsem script. Recommended now: option E, finish the queue with the rerun and time-limit changes, run observed_only by hand as a labelled mechanism arm, build the endsem around the layer, and build the oracle only if endsem is three weeks or more away and the queue finishes clean, one scene first, with a positive control.

## Threats to validity

- Wall-clock censoring is unequal across arms: the 4.5 h limit cut one official run at 54.3 m (hold-last biases it low) and will exclude the running 00853/44 official (18.6 m at 2.17 h); a placebo got 7.5 h (DEVIATIONS 10). Slow official runs are more likely to be censored or excluded, which selects on the outcome. Raising max_hours mid-campaign fixes this for remaining runs but makes them differ from completed cells; log it.
- Pilot status: placebo retry seeding and rerun salting changed after the frozen pre-registration; wave 1 was lost to a host OOM; E2 arms did not run alongside their official partners; wave 2 did not rotate container-to-arm assignments (not yet in DEVIATIONS). Every result must carry the 'pilot' label and the deviation list, which lives only on the host and in /tmp until copied into the repo.
- Dropped ensemble members (6 to 21% in official runs, 0 in placebo) make E1 'LLM content with fewer members' vs 'random content with all members'. Report the per-run drop rate as the pre-registered covariate.
- Pacing: placebo delay schedules are medians of earlier official runs, not the partner run's actual waits; the pre-registered flag (delay off by more than 20% at three or more stages) has no reported outcome in the files.
- Seeds pair the pipeline's own randomness (viewpoint sampling, perturbations, placebo draws) but not the LLM's token sampling, so the seed-paired sign-flip test is weak; keep it secondary. The blocked permutation is the main test, and with 2 scenes its floor is 0.005.
- Two scenes, both HM3D val, and the E1 sign differs between them; a 2-scene mean can hide a scene-specific effect in either direction.
- Run-to-run variation is large relative to the effects: the September old-model run on 00853 seed 42 scores 0.048 above the live seed-42 official; the 26 m calibration run on the same scene sits below the frontier where the 120 m run sits above. Within-arm SD (0.003 to 0.018) is estimated from 2 runs per cell; the MDE range 0.014 to 0.03 rests on that.
- The HM3D reference caps F1 for every arm (frontier P 0.60, R 0.26 at 95.7 m); the cap compresses differences between arms and would compress any oracle ceiling.
- The frontier comparator is one deterministic run per scene; its own-map inflation is scene-dependent (2.9x vs 4.5x at 60 m).
- The Gemini static test is exploratory: 29 vs 40 completions, inputs from failed-attempt runs, metric changed mid-test, one input scored twice for DeepSeek and placebo, unmatched input sets in the pooled numbers, sign test p = 0.07. Static placement precision predicts exploration gain weakly (decision-replay Spearman 0.27).
- The 2 m precision reading depends on the placebo being the right chance baseline; it draws labels from the same 1017 frequency table, so label frequency is matched, but frequent labels in dense rooms still inflate 2 m hits for both.
- observed_only is a different explorer (candidate set and gain both change), so placebo vs observed_only confounds 'hypotheses present' with 'candidate set changed'. It has never run live and may stall at the planning-error gate.
- An oracle arm, if built, gives the planner exact positions and detector-vocabulary labels no LLM has, bounds a nearby guesser because of the radial-range rule, and without a positive control an 'oracle equals placebo' result cannot be told from a frame or label bug.
- Shared host: two concurrent runs, other tenants' services, mapper memory growth of about 8 GB per hour per run; every wave so far has had an incident, so time estimates need failure headroom.
- The campaign cap ($20) can skip a paid launch silently; a skipped rerun would leave a cell at two seeds without anyone noticing unless the runner log is read.
